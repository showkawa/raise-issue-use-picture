# ADR-0004: 启动探测 + 缓存的能力分层；model 名可覆盖

- 状态：已接受
- 日期：2026-07-21

## 背景

作为通用网关，proxy 不能假设每个租户都有 Claude。M365 无官方"列出可用模型"API；唯一可靠手段是发不同 tone 看是否被接受（未知 tone 报 `Failed to invoke 'Chat'`）。

## 决策

- **启动时做一次轻量探测并缓存**（带 TTL，如 24h）：
  1. 逐个试候选 tone（`Claude_Sonnet` → `Gpt_5_5_Chat` → `Magic` …），记录被接受者；
  2. 对首个可用 Claude tone 发一次 fenced 探针确认能工具调用；
  3. 定档：Claude 可用且探针通过 → **T1**（默认 tone=`Claude_Sonnet`）；否则 → **T3**（GPT + 守卫，尽力而为，并在日志明确告警"未检测到 Claude，工具调用不可靠"）。
- **客户端可用 `model` 名显式覆盖**自动档选出的默认 tone。

## 理由

- 把不确定性挡在真实流量之前，行为可预期（通用网关尤其需要）。
- 相比"惰性首请求试错"，避免首个真实请求被拿来试错、体验不稳。

## 后果

- 启动有一次探测开销（可缓存摊薄）。
- 探测结果 → 策略选择须是开放枚举，便于未来补 T2（见 ADR-0001）。

# ADR-0006: 五守卫 + 共享 2 次重试预算 + 失败诚实上报

- 状态：已接受
- 日期：2026-07-21

## 背景

无 agent 时工具可靠性依赖纯客户端守卫。cramt 有多个运行时守卫；但每次重试都烧 M365 会话配额并加时延。实测：工具集规模是合规的主要影响因子；Disengaged 在 Claude tone 下不是主要瓶颈。

## 决策

实现五个守卫：

| 守卫 | 触发 | 动作 |
|---|---|---|
| confab 检测 | 带 tools 却回"无法访问/找不到/请粘贴内容" | 换 framing 重试 |
| 幻觉完成检测 | 声称已读/已改/结果是…却没发工具调用 | 重试并强调"必须先调用工具" |
| prose-document 防误执行 | 长文档内嵌代码块（非工具意图） | 不解析为工具调用，原样透传 |
| Disengaged 识别 | messageType=Disengaged / 空回复 | 新 conversation + softened framing 重试（**兜底**，非主力） |
| 429/throttle | 限流帧 / 配额 at-limit | 返回标准 OpenAI 429 + Retry-After |

- **重试预算**：所有守卫**共享每请求最多 2 次重试**。
- **失败诚实上报**：重试仍失败时返回诚实错误/原文，带 `x_m365_guard` 扩展字段说明发生了什么；**绝不伪造成功的工具调用**。
- **配套**：工具集瘦身（注入前压缩工具描述，保持"一个清晰示例 + 简洁清单"形状）。

## 理由

- 收紧重试预算避免烧配额/雪崩。
- 诚实上报让 agent 侧能正确反应（区分"该等"/"该改提示"）。

## 后果

- 高失败率场景（如 T3 的 GPT tone）即便重试也可能失败——如实告知，不掩盖。
- 合规率的量化对照（JSON vs fenced × Claude）待补探针数据（见 ADR-0002 待办）。
